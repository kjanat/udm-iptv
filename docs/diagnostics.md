# Diagnostics

Local snapshots, captures and failure output retain addresses and raw logs. Capture files use mode 0600 and identify themselves as private. Preserve these originals for analysis. Verbosity controls sampling frequency; it does not control privacy or telemetry consent.

`udm-iptv diagnose export CAPTURE.jsonl` writes the complete event records to stdout as JSON Lines. Add `--format text` for readable output with each complete JSON record alongside it. Logs, markers, addresses, DHCP options, journal metadata, large counters and fields from newer capture versions are retained. Export requires no router access or telemetry and never rewrites its input. Use the JSON Lines file created by `--format jsonl` or `--format both`.

Exports retain original addresses, subnet relationships and numerical ordering for querier election analysis. Older captures already labelled `sanitized` keep that label and any recorded alias-order metadata; exporting cannot recover content previously removed from those files.

Snapshots include configured values and observed state separately. Collection failures retain the affected source and error text, including partial results. Text includes snapshot timestamps, board and firmware identity, the raw firmware version, kernel, system state, unit results and exit status, generated proxy configuration, lease options and the exact managed address/route records. Periodic text samples retain their full snapshot.

Automatic failure diagnostics use the same report for local output and Sentry, including addresses, lease options and recent log messages. Reports larger than 256 KiB are attached as gzip files without truncating their content. A local output failure does not discard the telemetry attachment. Exception and panic messages retain their values. Saved telemetry settings control reporting. Telemetry delivery failures do not print automatic stderr warnings. Recent subprocess output is attached to failures within bounded tail buffers; routine output stays local.

Journal records arrive during capture rather than at finalization. Both the main service and firmware-restore service are included. The stream retains at most 10,000 records and 4 MiB of record input, with a 64 KiB limit per record; reaching a limit emits an explicit event describing missing evidence. Malformed records retain their raw content or bounded prefix and parse error. Journal command failures retain stderr and any collected stdout. Already queued records are drained when the capture ends; incomplete shutdown is recorded. One-shot and failure reports collect the most recent 100 records from both services in the current boot; `diagnose --verbosity debug` collects 300. Reports state that scope. Closing the viewer leaves the capture worker running until its deadline. Capture markers and lifecycle acknowledgements remain beside the original capture.
